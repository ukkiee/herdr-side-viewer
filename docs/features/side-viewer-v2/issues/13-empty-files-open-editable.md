# 13: 빈 마크다운·코드 파일을 바로 쓸 수 있게 열기

**What to build:** 비었거나 공백뿐인 마크다운 파일과 코드 파일을 열면 "이 파일은 비어 있습니다." 안내 대신 그 보기를 연다. 마크다운은 렌더링(맨 위 폴더·이름만 있는 빈 문서)과 "렌더링 | 원문" 전환이 있고, 원문은 빈(또는 그 공백의) 편집기라 바로 써서 저장할 수 있다. 코드 파일은 빈 코드 보기로 열려 바로 쓸 수 있다. 빈 svg·그림은 지금처럼 안내다.

**Blocked by:** 02, 04, 08 (모두 integrated)

**Status:** ready-for-agent

**명세:** `docs/features/side-viewer-v2/spec.md` (AC-22, AC-1·AC-19의 빈 파일 문장, "구현 결정"의 "빈 파일(AC-22)", "상태와 실패")

**결정 근거:** 2026-11-12 손 확인(RECIPE v2 1~6번) 중 사용자 제안("빈 md도 원문 렌더링 둘다 보이게")을 받아 범위를 "빈 md와 빈 코드 둘 다"로 합의했다(빈 svg·그림은 안내 유지).

**파일 소유:** `mods/side-viewer/views.js`와 그 테스트(빈 파일 판단, 연결 파일 자리), `mods/side-viewer/document.js`와 그 테스트(`contentOf`의 공백뿐인 글 판단), `mods/side-viewer/main.js`의 읽기 자리(필요할 때만), README.md·README.ko.md·RECIPE.md에서 빈 파일 안내를 말하는 문장(v1 Done when 13번, v2 5번, Limits·안내 목록 등)만.

**설계 계약:**
- 보기 판별·읽기: v1 명세 `docs/features/side-viewer/spec.md`의 "구현 결정"("보기 판별", "새로고침")과 AC-9, 이 명세의 "구현 결정"("보기 판별", "빈 파일(AC-22)")
- 편집·저장: 티켓 02·03의 편집 상태(`edit-state.js`)와 `editedContentOf`(티켓 02 Comments, 리뷰 F1·RV2-1): 고친 파일이 비게 된 경우의 동작과 맞춘다
- 마크다운 보기: 티켓 04의 `markdown-view.js`(빈 문서도 맨 위 폴더·이름)
