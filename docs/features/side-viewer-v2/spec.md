# 명세: 사이드 뷰어 v2

Status: ready-for-agent

통합 기준: 브랜치 `feat/side-viewer-v2`, 기준 SHA `ead36fd3130fa0fb4901c3ca7fb760c8dbd60eb1` (`main`)

용어는 루트 `GLOSSARY.md`를 따른다. 여는 방법의 결정 근거는 `docs/adr/0001-cmd-click-through-a-default-app-router.md`이고, v1의 동작과 결정은 `docs/features/side-viewer/spec.md`다. 이 명세가 바꾸지 않은 v1 동작은 그대로 유지한다.

## 문제

사이드 뷰어는 파일을 보여 주기만 한다. 에이전트가 쓴 계획 문서나 코드에서 한 줄을 고치려면 다른 편집기로 넘어가야 한다. 대화 옆 pane은 좁아서 긴 문서를 넓게 보려면 방법이 없다. 마크다운 보기는 내장 TextView 한 장이라 코드 블록에 색이 없고, 복사할 수 없고, 본문 그림이 나오지 않는다. 코드 파일 열기는 v1에서 선택 사항이고 `html`은 열리지 않는다.

## 해결

마크다운·svg의 원문 보기와 코드 보기에서 파일을 고치고 cmd+S나 저장 버튼으로 저장한다. 저장하지 않은 수정은 뷰어가 기억하고, 그사이 파일이 밖에서 바뀌면 덮어쓰지 않고 물어본다. 머리줄의 "새 탭으로 열기"로 같은 파일을 뷰어만 있는 탭에 넓게 띄운다. 마크다운 보기는 Warp의 마크다운 보기를 본떠 블록마다 직접 그린다. 코드 블록은 언어 이름, 복사 버튼, 셸 명령을 터미널에 넣는 버튼이 달린 카드가 되고, 본문 그림이 보인다. 코드 묶음에 `html`·`htm`이 들어가고, svg는 그림과 원문을 오간다.

## 사용자 스토리

1. Herdr 사용자로서, 사이드 뷰어의 원문 보기에서 계획 문서의 한 줄을 바로 고치고 싶다. 다른 편집기로 넘어가지 않기 위해서다.
2. Herdr 사용자로서, 코드 파일을 사이드 뷰어에서 열어 그 자리에서 고치고 싶다.
3. Herdr 사용자로서, svg를 그림으로 보다가 원문으로 바꿔 고치고, 고친 결과를 저장 전에 그림으로 확인하고 싶다.
4. Herdr 사용자로서, cmd+S나 머리줄 버튼으로 저장하고, 저장하지 않은 수정이 있다는 것을 한눈에 알고 싶다.
5. Herdr 사용자로서, 고치다가 다른 파일을 보고 돌아와도 고친 내용이 남아 있길 원한다.
6. Herdr 사용자로서, 내가 고치는 동안 에이전트가 같은 파일을 바꾸면 내 수정이 조용히 덮이지도, 에이전트의 수정을 조용히 덮지도 않길 원한다.
7. Herdr 사용자로서, 저장이 실패하면 이유를 보고 수정은 잃지 않길 원한다.
8. Herdr 사용자로서, 마크다운 원문을 고치다가 렌더링으로 바꾸면 저장 전 수정이 반영된 모습을 보고 싶다.
9. Herdr 사용자로서, 원문 보기에서는 긴 문단이 pane 폭에서 접혀 가로 스크롤 없이 읽히길 원한다.
10. Herdr 사용자로서, 대화 옆에서 보던 문서를 뷰어만 있는 탭으로 넓게 띄우고 싶다.
11. Herdr 사용자로서, 뷰어 탭의 이름이 보고 있는 파일 이름이길 원한다. 탭이 여러 개일 때 찾기 위해서다.
12. Herdr 사용자로서, 고치던 문서를 새 탭으로 옮기면 수정도 따라오길 원한다.
13. Herdr 사용자로서, 뷰어 탭을 보고 있을 때 cmd-클릭한 파일이 그 탭에 열리길 원한다.
14. Herdr 사용자로서, 마크다운 문서를 폭 제한 없이 Warp처럼 읽기 좋게 보고 싶다.
15. Herdr 사용자로서, 문서 안 코드 블록을 언어 색과 함께 카드로 보고 버튼 하나로 복사하고 싶다.
16. Herdr 사용자로서, 문서 안 셸 명령을 버튼 하나로 터미널 입력 칸에 넣고, 확인한 뒤 내가 Enter를 누르고 싶다.
17. Herdr 사용자로서, 목록이나 인용 안의 코드 블록도 같은 카드로 보고 싶다.
18. Herdr 사용자로서, 마크다운 안의 로컬 그림을 문서 안에서 보고 싶다.
19. Herdr 사용자로서, 표·목록·체크박스·인용·각주가 구분되어 보이길 원한다.
20. Herdr 사용자로서, 코드 블록을 눌러도 편집할 수 있는 것처럼 커서가 깜빡이지 않길 원한다.
21. Herdr 사용자로서, `html` 파일도 cmd-클릭으로 사이드 뷰어에서 열고 고치고 싶다.
22. macOS 사용자로서, 코드 묶음 넘겨받기는 여전히 내가 고를 때만 일어나길 원한다.

## 인수 조건

검증 경계는 아래 "테스트 결정"의 네 가지를 가리킨다. "고칠 수 있는 보기"는 마크다운 원문 보기, svg 원문 보기, 코드 보기 세 가지다.

### 편집과 저장

| ID | 관측할 결과 | 검증 경계 |
|---|---|---|
| AC-1 | 고칠 수 있는 보기에서는 글자를 입력·삭제할 수 있다. 마크다운 렌더링(체크박스는 AC-21), 이미지 보기(svg 렌더링 포함), 코드 블록 카드, 안내 화면에서는 고칠 수 없다. 빈 마크다운·svg는 안내와 함께 원문 전환이 있고, 빈 코드 파일은 고칠 수 있는 보기로 열린다(AC-22). svgz는 원문 보기가 없다. | 경계 1, 경계 4 |
| AC-2 | 고친 뒤 저장하기 전에는 머리줄에 "저장 안 됨"과 저장 버튼이 보인다. 고친 내용이 없으면 둘 다 보이지 않는다. cmd+S나 저장 버튼을 누르면 파일에 쓰고 둘 다 사라진다. 고친 내용이 없을 때 cmd+S는 아무 일도 하지 않는다. 고친 내용을 원래대로 되돌리면 둘 다 사라진다. 자동 저장은 없다(체크박스는 AC-21의 예외). | 경계 1, 경계 4 |
| AC-3 | 저장하지 않은 수정은 그 뷰어 사본 안에 파일별로 남는다. 링크·뒤로 가기·새 열기 요청으로 다른 파일로 갔다가 같은 파일로 돌아오면 고친 내용과 "저장 안 됨"이 되살아난다. pane을 닫거나 Herdr를 끄면 사라지고, 묻는 창은 없다. | 경계 1, 경계 4 |
| AC-4 | 고친 내용이 있을 때 파일이 디스크에서 바뀌면 다시 읽지 않고, 내용 위에 "밖에서 바뀌었습니다" 막대를 띄운다. 막대에는 [내 수정 버리고 다시 읽기]와 [내 것으로 덮어쓰기]가 있다. 버리기는 디스크 내용을 보여 주고 "저장 안 됨"을 지운다. 덮어쓰기는 내 내용을 저장한다. 저장하는 순간 디스크 내용이 뷰어가 마지막으로 읽은 내용과 다르면 쓰지 않고 같은 막대를 띄운다. 고친 내용이 없으면 v1처럼 알아서 다시 읽는다. | 경계 1, 경계 4 |
| AC-5 | 저장이 실패하면(권한 없음, 파일이 지워짐, 1 MiB 초과) 같은 막대 자리에 이유를 보여 주고 고친 내용은 그대로 남는다. 어떤 경우에도 mod 오류가 나지 않는다. | 경계 1, 경계 3, 경계 4 |
| AC-6 | 원문 보기에서 고친 뒤 렌더링으로 바꾸면, 마크다운은 고친 내용으로 그린 문서를, svg는 고친 내용으로 그린 그림을 보여 준다. 파일에는 쓰지 않는다. | 경계 1, 경계 4 |
| AC-7 | 원문 보기는 긴 줄을 pane 폭에서 접어 보여 준다. 코드 보기는 접지 않는다. 둘 다 줄 번호가 있다. | 경계 4 |

### 마크다운 보기

| ID | 관측할 결과 | 검증 경계 |
|---|---|---|
| AC-12 | 마크다운 렌더링은 읽기 폭 제한 없이 pane 폭을 쓰고 본문은 13pt다. 문서 맨 위에 폴더(흐리게)와 파일 이름이 있다. 머리줄에는 "렌더링 \| 원문" 두 칸 전환이 있고, cmd+E 단축키는 없다. | 경계 3, 경계 4 |
| AC-13 | 블록마다 따로 그린다. 제목은 단계별 크기(1·2·3단계 24·19·16pt, 4단계 이하는 13pt 굵게)에 밑줄이 없다. 목록은 첫 단계 채운 점, 둘째 단계 빈 점, 번호, 체크박스(누르기는 AC-21)로 그리고, 빈 줄로 나뉜 다른 종류의 목록은 따로 그린다. 표는 내용 폭에 맞추고 머리 칸은 굵게, 줄 사이에만 선을 긋고, 칸 정렬(왼쪽·가운데·오른쪽)을 따른다. 구분선은 두꺼운 선이다. 인용은 왼쪽 막대와 흐린 글자로 그리고 안의 블록도 같은 규칙으로 그린다. 각주는 본문에 위첨자 번호, 문서 끝에 내용 목록으로 그린다. 문단 안의 링크·굵게·기울임·인라인 코드·취소선은 v1처럼 동작한다. | 경계 1, 경계 4 |
| AC-14 | 줄 하나를 차지하는 로컬 그림(문서 폴더 기준 상대 경로, 절대 경로)이 문서 안에 보인다. pane 폭에 맞추되 원래 크기보다 키우지 않고, 높이는 최대 420이며 가운데 정렬한다. 그림을 읽을 수 없으면 그 자리에 "그림을 못 읽음: <경로>"를 보여 준다. | 경계 1, 경계 4 |
| AC-15 | 코드 블록은 카드로 그린다. 모서리는 둥글고 테두리가 있으며, 어두운 테마에서는 위에서 아래로 어두워지는 그라데이션, 밝은 테마에서는 단색이다. 왼쪽 아래에 언어 이름(아는 언어는 이름표, 셸 계열은 "Shell", `mermaid`는 "Mermaid", 그 밖은 "Code"), 오른쪽 아래에 복사 버튼이 있다. 복사 버튼은 블록 전체를 클립보드에 넣고 잠시 체크 표시로 바뀐다. 문법 색이 있다. 긴 줄은 카드 안에서 접히고, 카드 높이는 내용에 맞아 카드 안에 스크롤이 없으며, 카드 위에서 휠을 굴리면 문서가 스크롤된다. 카드를 눌러도 커서가 생기지 않고 글자를 고를 수 없다. 목록 안의 코드 블록은 항목 글자에 맞춰 들여 쓴 카드, 인용 안의 코드 블록은 인용 막대 안의 카드다. | 경계 1, 경계 4 |
| AC-16 | 언어가 없거나 `sh`·`shell`·`bash`·`zsh`·`fish`·`console`인 코드 블록 카드에는 `>_` 버튼이 있다. 누르면 그 뷰어 아래에 셸 pane을 열고 명령을 입력 칸에 넣는다. Enter는 누르지 않고 클립보드는 바뀌지 않는다. 셸의 폴더는 사이드 뷰어 옆 대화 터미널의 폴더이고, 뷰어 탭이면 문서의 폴더다. 다시 누르면, 그 셸 pane이 살아 있으면 같은 pane에 넣는다. 그 셸이 다른 프로그램을 실행 중이면 넣지 않고 이유를 알린다. 이 바쁜 상황은 경계 4에서 실제로 만들어(셸 pane에서 오래 도는 명령을 실행한 채 `>_`를 누름) 사용자에게 보여 준다. | 경계 1, 경계 4 |
| AC-21 | 렌더링의 체크박스를 누르면 체크가 바뀌고 원문의 그 줄이 `[ ]`↔`[x]`로 바뀐다. 그 파일에 고친 내용이 없으면 바로 파일에 저장한다. 저장하는 순간 디스크 내용이 뷰어가 마지막으로 읽은 내용과 다르면 쓰지 않고 AC-4의 막대를 띄운다. 고친 내용이 있으면 그 수정에 더해지고 "저장 안 됨"으로 남는다. | 경계 1, 경계 4 |

### 파일 종류

| ID | 관측할 결과 | 검증 경계 |
|---|---|---|
| AC-17 | 코드 묶음에 `html`·`htm`이 들어간다. 코드 묶음을 넘겨받은 Mac에서 이 파일을 cmd-클릭하면 코드 보기(고칠 수 있음)로 열린다. 코드 묶음은 v1처럼 `--make-default code`로만 넘겨받고, 넘겨받기 전 안내의 확인 창 수가 새 목록에 맞다. | 경계 1, 경계 2, 경계 4 |
| AC-18 | svg는 처음에 그림으로 열리고, 머리줄의 "렌더링 \| 원문"으로 원문(고칠 수 있는 코드 보기)과 오간다. | 경계 1, 경계 4 |
| AC-22 | 비었거나 공백뿐인 마크다운 파일과 svg 파일은 머리줄에 "렌더링 \| 원문" 전환이 있고, 렌더링 쪽은 "이 파일은 비어 있습니다." 안내를 보이며, 원문은 빈(또는 그 공백의) 편집기(svg는 색상 언어 `xml`)라 바로 쓸 수 있다. 쓴 뒤 렌더링으로 바꾸면 쓴 글로 그린 문서·그림을 보인다(AC-6). 비었거나 공백뿐인 코드 파일은 빈 코드 보기(고칠 수 있음)로 열린다. 쓰고 cmd+S나 저장 버튼을 누르면 파일에 쓴다(AC-2와 같은 규칙). 빈 svgz·그림(png 등)은 v1처럼 안내만이다. | 경계 1, 경계 3, 경계 4 |

## 구현 결정

- **고칠 수 있는 보기.** 원문 보기와 코드 보기는 v1의 읽기 전용 편집기 상태를 고칠 수 있게 바꾼다. 원문 보기는 줄 접기를 켜고 코드 보기는 끈다. 편집기 상태는 그리는 도중에 만들 수 없다(2026-11-12 시안에서 "EditorState.new(...) cannot run during render" 오류를 관측). 그래서 파일을 읽은 뒤나 이벤트 처리 안에서 만든다.
- **편집 상태(새 순수 모듈).** 뷰어 사본마다 파일별로 "마지막으로 읽은 디스크 내용"과 "고친 내용"을 들고 있다. 이 모듈이 정하는 것: 저장 안 됨 여부(두 내용이 다름), 디스크 변경을 받았을 때 할 일(고친 내용이 없으면 다시 읽기, 있으면 막대), 저장 결과의 해석(성공, 밖에서 바뀜, 권한 없음, 지워짐, 너무 큼), 막대의 두 버튼 뒤의 상태. Herdr를 부르지 않아서 `node --test`로 돈다.
- **저장.** `herdr`의 `writeTextFile(path, text, expected)`에 마지막으로 읽은 디스크 내용을 `expected`로 넘긴다. 이 함수는 파일이 `expected`와 다르면 쓰지 않고 거부한다(`herdr.d.ts`의 설명). 거부는 AC-4의 막대로 이어진다. 1 MiB(1,048,576바이트) 초과는 쓰기 전에 막는다.
- **cmd+S.** mod를 `"focusable": true`로 하고, 포커스 핸들과 `on_key_down`으로 `cmd-s`를 받는다. Herdr의 `keys.json`과 앱 메뉴에 cmd+S가 없다는 것은 소스와 설정 파일로 본 것이다실제 앱에서 바깥 핸들에 포커스가 있을 때와 안의 고칠 수 있는 편집기에 포커스가 있을 때 모두 cmd+S가 `on_key_down`에 `"cmd-s"`로 오고 편집기에 글자가 들어가지 않았다(2026-11-12 시험 mod로 관측, 티켓 02 Comments).
- **렌더링 미리 보기.** 렌더링으로 바꿀 때 고친 내용이 있으면 그 글로 블록을 다시 해석해 그린다. svg는 고친 글을 데이터 폴더의 임시 사본으로 써서 그린다.
- **뷰어 탭.** `herdr-app do tab.new`(mod, props, name)로 만들고 `tab.move`로 지금 탭 바로 뒤에 놓고, 파일이 바뀌면 `tab.rename`으로 이름을 바꾼다. 고친 내용을 넘길 때는 v1의 요청 방식처럼 데이터 폴더에 넘김 파일을 쓰고 새 탭의 props에는 그 ID만 넣는다. 원래 뷰어는 넘긴 뒤 그 파일의 고친 내용을 지운다. 열기 요청은 v1처럼 화면에 보이는 사본이 받으므로, 보이는 뷰어 탭이 받는다.
- **마크다운 블록 해석(새 순수 모듈).** 해석하는 것: 제목, 문단, 목록(항목 단계, 번호, 체크박스, 항목 아래 코드 블록), 인용(안의 블록을 다시 해석), 표(칸 정렬 포함), 구분선, 줄 하나짜리 그림, 각주 정의, 코드 블록(언어). 빈 줄로 나뉜 목록은 다음 항목이 같은 종류(점, 번호, 체크박스)이거나 들여 쓴 줄일 때만 이어진다. 블록 안의 글은 TextView로 그린다. mod에는 글자 단위 스타일을 줄 방법이 없어서다(`미확인`: `gpui-kit.d.ts` 검색 기준).
- **코드 블록 카드.** 문법 색은 편집기 상태(읽기 전용, 줄 접기, 줄 번호와 접기 표시 없음)로 낸다. 편집기는 마지막 줄 아래에 편집기 높이의 절반, 최소 3줄의 빈 공간을 두고 스크롤을 허락한다(gpui-kit 소스 `input/base/element.rs`의 `empty_bottom_height`, 2026-11-12 시안에서 짧은 블록의 스크롤바로 관측). 그래서 편집기를 `max(2×줄 수, 줄 수+3)+1`줄 높이로 그리고 바깥 상자에서 글 높이만큼만 보이게 자른다. 그러면 스크롤할 것이 없어 휠이 문서로 간다(편집기는 스크롤 위치가 실제로 바뀔 때만 휠을 멈춘다, 같은 파일). 접힌 줄 수는 카드 폭과 고정폭 글자 폭(글자 크기의 0.6배, 한글은 두 칸)으로 어림한다. 편집기 위에는 누름을 삼키는 투명한 막을 덮는다. 편집기는 포커스가 있으면 커서를 늘 그리고, mod에서 커서를 끄거나 색을 바꿀 방법이 없다(`미확인`: 소스와 `gpui-kit.d.ts` 기준. 포커스 없이는 끌어 고르기가 되지 않는다는 것도 소스 기준).
- **카드 모양(시안 값).** 모서리 8, 테두리 1(`border`), 그라데이션은 위 `surface`에서 아래 `background`와 검정을 3:1로 섞은 색, 밝은 테마는 `surface` 단색. 코드 글자 13px, 줄 높이 21. 안쪽 여백 위 16·왼쪽 16 안팎, 아래에 언어 이름(12px, `muted`)과 16px 아이콘. 카드 사이 간격 16.
- **언어 이름표와 셸 판정(순수).** 확장자처럼 코드 블록 언어 → 편집기 색상 언어, 이름표, 셸 여부를 정한다. 셸 계열은 언어 없음, `sh` `shell` `bash` `zsh` `fish` `console`이다.
- **터미널에 넣기.** 셸 pane은 `herdr-app do pane.split`(아래, 터미널)로 열고 이 뷰어가 연 셸 pane을 기억한다. 명령을 Enter 없이, 클립보드를 거치지 않고 입력 칸에 넣는 방법은 구현 첫 단계에서 실측으로 정한다. 후보는 `hc keys`로 한 글자씩 누르기, zsh의 `print -z`다. `hc send`는 붙여 넣은 뒤 Enter를 누르고 Enter를 끄는 옵션이 없다(`미확인`: `hc send --help` 기준). 어느 후보도 조건을 채우지 못하면 구현을 멈추고 사용자에게 묻는다. 셸이 바쁜지는 `hc get`의 상태로 본다.
- **본문 그림.** TextView는 `data:` 주소로 넣은 로컬 그림을 그리지 않았다(2026-11-12 시안 F에서 관측). 그래서 v1 이미지 보기의 사본 방식(머리 바이트 확인, 데이터 폴더 사본, `image()`)을 본문 그림에도 쓴다. 크기는 `sips`가 아니라 v1의 `sizeOf`로 읽는다.
- **svg 전환.** svg는 이미지 보기로 시작하고, 원문은 코드 보기(색상 언어 `xml`)다. svgz는 압축 파일이라 원문 보기가 없다.
- **html.** 확장자 목록의 코드 묶음에 `html`·`htm`을 넣고 색상 언어는 `html`(편집기가 모르면 `xml`)이다. macOS가 html 파일 종류에 묶는 형제 확장자와 확인 창 수는 v1처럼 실측해 목록과 안내에 반영한다. 기본 브라우저를 바꿀 때 macOS가 html 기본 앱을 브라우저로 되가져가는지는 `미확인`이다.
- **화면.** 머리줄은 v1 구성(뒤로 가기, 파일 이름·폴더, 원래 앱으로 열기, Finder에서 보기)에 "렌더링 \| 원문" 두 칸 전환, 새 탭으로 열기, 그리고 고친 내용이 있을 때만 "저장 안 됨"과 저장 버튼을 더한다. 좁아지면 v1처럼 이름과 폴더를 말줄임하고 버튼은 남긴다. 안내 문구: "저장 안 됨", "밖에서 바뀌었습니다", "내 수정 버리고 다시 읽기", "내 것으로 덮어쓰기", "그림을 못 읽음: <경로>", 저장 실패 이유("이 파일에 쓸 권한이 없습니다.", "파일이 지워졌습니다.", "저장하기에는 너무 큽니다.", 그 밖의 실패는 "저장하지 못했습니다: <오류>"(티켓 03에서 정함)).
- **보기 판별.** `views.js`가 svg의 전환 가능 여부와 html을 다루도록 넓힌다. 고칠 수 있는지도 여기서 정한다.
- **빈 파일(AC-22).** 2026-11-12 손 확인 중 사용자가 정했다: 빈 파일을 열어 바로 쓸 수 있게 한다. 처음에는 빈 마크다운·코드 파일을 안내 없이 그 보기로 열기로 했다(티켓 13). 손 확인에서 사용자가 "empty.md도 안내는 해주되 고를 수 있게, svg도 렌더링 원문 보이게"로 고쳤다(티켓 14): 빈 마크다운·svg는 렌더링 쪽에 "비어 있음" 안내를 보이고 "렌더링 \| 원문"으로 빈 편집기를 고를 수 있다. 빈 코드 파일은 전환이 없는 보기라 빈 편집기로 연다. 원문이 없는 svgz·그림은 안내만 남긴다. v1 AC-9의 빈 파일 항목을 이 세 경우에서만 바꾼다. 렌더링의 "비어 있음" 안내는 보이는 글(저장 안 한 수정 포함, AC-6과 같은 규칙) 기준이라, 고친 글을 다 지워도 렌더링 쪽에 이 안내가 보인다("저장 안 됨"이 함께 보인다). svg가 비었는지는 파일 첫 4 KiB 안이 0바이트이거나 ASCII 공백뿐인지로 본다. 그보다 긴 공백이나 비ASCII 공백(NBSP 등)뿐인 svg는 svg가 아니라서 "열 수 없음" 안내가 나온다(티켓 14 리뷰 R14-1, 범위로 받아들임).
- **체크박스 바꾸기(순수).** 블록 해석이 체크박스 항목마다 원문의 줄 번호를 기억하고, 바꾸기 함수가 그 줄의 `[ ]`와 `[x]`(`[X]` 포함)만 바꾼 글을 돌려준다. 고친 내용이 있으면 고친 글에, 없으면 디스크 글에 적용한다. 저장은 AC-4와 같은 `expected` 규칙을 쓴다.

## 참고

- **`/tmp` 경로 클릭.** 경로 바로 뒤에 한글이 붙으면(`/tmp/notes/plan.md에서`) Herdr가 붙은 글자까지 경로로 읽어 파일을 찾지 못한다. 띄어 쓴 경로는 열렸다(2026-11-12 관측). 그래서 mod를 고치지 않고, 답변에서 경로 뒤를 띄어 쓰라는 규칙을 공용 지침(`~/.codex/AGENTS.md`)에 넣었다.
- **Warp 마크다운 보기 조사.** Warp 0.2026.11.04에 시험 파일을 열어 확인했다(2026-11-12). 코드 카드 모양과 색, `>_` 동작, 셸 판정 목록, 표·목록 모양을 여기서 가져왔다. Warp는 인용·기울임·각주·수식·HTML 태그를 그리지 않지만 사이드 뷰어는 인용·기울임·각주를 그린다.
- **시안.** 모양 시안 A~F를 Herdr에 띄워 비교했고 F("Warp + 블록별")를 골랐다. 시안 코드는 사용자 요청으로 2026-11-12에 지웠고(커밋하지 않음), 고른 모양의 값과 요령은 이 명세의 "구현 결정"에 적었다. 시험 문서 `docs/features/side-viewer-v2/markdown-sample.md`(모든 마크다운 요소)와 `docs/features/side-viewer-v2/code-sample.md`(언어별·긴 줄·목록 속·인용 속 코드 블록)는 경계 4에서 쓴다.
