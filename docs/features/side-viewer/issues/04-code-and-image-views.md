# 04: 코드 보기, 이미지 보기, 그릴 수 없는 파일 안내

**What to build:** 사이드 뷰어가 확장자에 따라 보기를 고른다. 코드·텍스트는 줄 번호와 문법 색상이 있는 읽기 전용 코드 보기, 이미지는 뷰어 폭을 넘지 않는 그림이다. 그릴 수 없는 파일(1 MB 초과 텍스트, 20 MB 초과 이미지, 넘겨받은 확장자가 아닌 파일, 읽을 수 없는 파일)은 이유 안내만 보여 주고 mod 오류를 내지 않는다.

**Blocked by:** 02

**Status:** ready-for-agent

**명세:** `docs/features/side-viewer/spec.md` (AC-3, AC-9)

**파일 소유:** 보기 판별 모듈과 이미지 사본 관리 모듈(새 파일, `mods/side-viewer/` 아래)과 그 테스트. 연결 파일: `mods/side-viewer/main.js`의 본문 그리기 분기 자리. 확장자 목록 파일은 읽기만 한다(소유 01).

**설계 계약:**
- 보기 판별 모듈: 명세 "구현 결정"의 "보기 판별", AC-3·AC-9의 확장자와 크기 숫자
- 이미지 사본 관리 모듈: 명세 "구현 결정"의 "이미지 그리기"(확장자와 머리 바이트 확인, 30일 정리)
- `main.js`의 해당 자리: 명세의 연결 파일 표, `~/.config/herdr-app/AGENTS.md`의 "UI" 절(`EditorState`·`Editor`, `image`)

**검증 방법:**
- 경계 1: 확장자 → 보기·색상 언어, 크기 경계값(정확히 1 MB/20 MB, 그 초과), 이미지 머리 바이트 판별 단위 테스트
- 경계 3: `herdr-app check mods/side-viewer`
- 경계 4: 실제 앱에서 코드 파일, 이미지, 큰 파일을 열어 확인

- [ ] 코드·텍스트 파일이 줄 번호와 문법 색상이 있는 읽기 전용 화면으로 보인다
- [ ] 색상 언어를 모르는 확장자는 색 없이 보이고 오류가 없다
- [ ] 이미지가 뷰어 폭을 넘지 않게 보이고, 뷰어를 좁히면 따라 줄어든다
- [ ] 확장자는 이미지지만 내용이 이미지가 아닌 파일은 사본을 만들지 않고 안내를 보여 준다
- [ ] 1 MB 초과 텍스트, 20 MB 초과 이미지, 넘겨받은 확장자가 아닌 파일, 읽을 수 없는 파일이 각각 이유 안내로 보인다
- [ ] `herdr-app check`가 통과한다

**완료 조건:** 위 항목 전부, 경계 1 테스트와 경계 3 통과.

## Comments

### 2026-11-11 구현 메모

- **모듈.** `views.js`(확장자 → 보기·색상 언어, 크기 제한, 파일을 읽기 전에 묻는 스크립트 `PROBE`와 그 해석, 다시 읽었을 때 화면을 바꿀지의 판단), `image-copies.js`(머리 바이트로 이미지 종류 판별, 사본 이름, 이미지 크기 읽기, 폭 맞춤, 30일 정리 대상). `document.js`의 `contentOf(file, text, found)`는 `views.js`의 판별 결과를 받는다.
- **확장자 목록 읽기.** mod는 JSON을 import할 수 없고(`herdr-app check`에서 JS로 해석돼 실패) `import.meta.url`도 없다. 그래서 `${appHome()}/mods/side-viewer/extensions.json`을 실행 중에 읽는다. mod가 앱 홈에 설치돼 있지 않으면 목록을 못 읽어 모든 파일이 "이 종류의 파일은 뷰어에서 열 수 없습니다."가 된다(분기 스크립트는 미설치일 때 애초에 뷰어로 보내지 않는다).
- **크기.** `fs/promises`에 stat이 없어 `exec("sh", …)`로 `stat`을 부른다(크기, 수정 시각, 첫 4096바이트). 1,048,576바이트와 20,971,520바이트는 그리고 1바이트라도 넘으면 안내한다.
- **이미지.** 머리 바이트가 PNG·JPEG·GIF·WebP·SVG인 파일만 `data/side-viewer/images/<경로 해시>-<크기>-<수정 시각>.<종류>`로 복사한다(권한 600). `.svgz`는 gzip 머리만 확인한다. 이미 있는 사본은 `touch`만 하고, 뷰어 사본당 한 번 30일 넘게 안 쓴 사본을 지운다. 내용이 이미지가 아니면 사본 없이 "이 종류의 파일은 뷰어에서 열 수 없습니다."를 보여 준다.
- **다시 읽기.** 같은 파일을 다시 읽을 때는 "불러오는 중…"으로 바꾸지 않고, 내용이 같으면 화면을 건드리지 않는다. 코드가 바뀌면 편집기 상태는 그대로 두고 `set_value`로 글만 바꾼다.
- **색상 언어 이름.** 편집기가 아는 이름 목록은 문서에 없다. 모르는 이름은 오류 없이 색 없이 그려지는 것을 임시 사본의 check로 확인했다. `toml`·`swift`·`kotlin`·`scss`·`xml`은 추측한 이름이라 색이 안 나올 수 있다.
- **미검증(경계 4).** 실제 앱에서 코드·이미지·큰 파일 열기, 이미지가 사본 경로에서 실제로 그려지는지와 원본 경로를 직접 그릴 수 있는지, `.svgz`가 그려지는지, 뷰어를 좁힐 때 이미지가 따라 줄어드는지, 테마를 바꾼 뒤 열려 있던 코드 보기의 색(편집기 상태를 만들 때의 색으로 고정된다).
