# 05: 자동 새로고침, 머리줄 버튼, 마크다운 링크

**What to build:** 보고 있는 파일이 디스크에서 바뀌면 사이드 뷰어가 스스로 갱신되고, 파일이 사라지면 안내로 바뀌었다가 다시 생기면 내용이 돌아온다. 머리줄에 원문/렌더링 전환(마크다운만), "원래 앱으로 열기", "Finder에서 보기"가 생긴다. 마크다운 보기 안의 링크는 마크다운 파일이면 같은 뷰어에서 열고, 웹·메일 주소는 시스템 기본 처리기로, 그 밖의 로컬 파일은 Finder 위치만 보여 준다. 그릴 수 없는 파일 안내 화면에도 두 버튼이 보인다.

**Blocked by:** 02

**Status:** integrated

**명세:** `docs/features/side-viewer/spec.md` (AC-6, AC-7, AC-8, AC-9 중 안내 화면의 버튼)

**파일 소유:** 마크다운 링크 처리 모듈(새 파일, `mods/side-viewer/` 아래)과 그 테스트, 머리줄 아이콘 파일. 연결 파일: `mods/side-viewer/main.js`의 머리줄 버튼·파일 감시·링크 처리 자리.

**설계 계약:**
- 링크 처리 모듈: AC-7(대상별 동작, 상대 링크의 기준 폴더, 로컬 파일은 실행하지 않음)
- 파일 감시: 명세 "구현 결정"의 "새로고침"(`watchFolder`와 15초 재확인), `~/.config/herdr-app/AGENTS.md`의 "Files" 항목과 "Animate natively, never with a timer" 규칙
- "원래 앱으로 열기": 명세 "구현 결정"의 "원래 앱 기록"(형식 소유 01), AC-8의 "라우터로 되돌아오지 않는다"
- 아이콘 파일: 없음 (`AGENTS.md`, `docs/adr/`, 명세 확인. 참고 레포 RECIPE는 mod 폴더가 링크일 때 `svg("mods/...")`가 빈 화면이 된다고 적었으나 이 저장소에서는 미확인)

**검증 방법:**
- 경계 1: 링크 처리 단위 테스트(상대·절대·`~/`·`file://`·`http(s)`·`mailto`·앵커만 있는 링크·마크다운 아닌 로컬 파일)
- 경계 2: "원래 앱으로 열기"가 원래 앱 기록의 앱을 지정해 부르는지(라우터로 되돌아오지 않는지) 확인
- 경계 3: `herdr-app check mods/side-viewer`
- 경계 4: 실제 앱에서 파일 수정·삭제·복원, 버튼 둘, 링크 종류별 클릭

- [ ] 보고 있는 파일을 고치면 클릭 없이 내용이 갱신된다
- [ ] 파일을 지우면 "이 파일은 더 이상 없습니다." 안내가 보이고, 다시 만들면 내용이 돌아온다
- [ ] 원문/렌더링 전환이 마크다운에서만 보이고 동작한다
- [ ] "원래 앱으로 열기"가 원래 앱에서 열고 사이드 뷰어로 되돌아오지 않는다
- [ ] "Finder에서 보기"가 그 파일을 선택한 Finder 창을 연다
- [ ] 마크다운 링크가 대상 종류별로 AC-7대로 동작하고, 마크다운 링크로 연 문서는 뒤로 가기 기록에 쌓인다
- [ ] 뷰어를 좁히면 이름과 폴더가 말줄임되고 버튼은 남는다
- [ ] `herdr-app check`가 통과한다

**완료 조건:** 위 항목 전부, 경계 1·2 테스트와 경계 3 통과. 뒤로 가기 기록에 쌓이는 항목은 03이 통합된 뒤 확인한다(03 미통합이면 06에서 확인하도록 Comments에 남긴다).

## Comments

### 2026-11-11 구현 메모

- **모듈.** `links.js`(링크 대상별 동작 `linkAction`, 원문 보기용 `rawMarkdown`, 감시 판단 `touches`·`folderOf`, `isMarkdown`), `original.js`(원래 앱 판단 `originalApps`·`openOriginalCommands`). 아이콘 `source.svg`·`rendered.svg`·`original.svg`·`finder.svg`.
- **"원래 앱으로 열기".** 설치된 라우터 앱의 스크립트를 부르지 않고, mod가 `original-apps.tsv`와 `extensions.json`을 읽어 `open -b <번들ID> <파일>`을 직접 부른다. 라우터 앱의 설치 위치에 기대지 않기 위해서다. 기록 없음·기록이 라우터 자신이면 TextEdit(이미지는 미리보기), 기록된 앱이 실패하면 기본값으로 한 번 더 시도한다. `router/open-original.sh`와 같은 앱을 고르는지 테스트가 가짜 `open`으로 대조한다.
- **원문 보기.** 원문을 코드 펜스로 감싸 같은 `TextView.markdown`으로 그린다(선택·복사 가능, 줄 번호·색 없음). 04의 코드 보기가 통합되면 그쪽 편집기로 바꿀 수 있다.
- **감시.** `watch(cx)`는 `this.file`의 폴더가 바뀌었을 때만 감시를 새로 건다. `init` 끝과 링크 이동 뒤, 15초 재확인 때마다 부른다. 03이 `show`로 파일을 바꾼 직후에도 `this.watch(cx)`를 불러야 새 폴더를 바로 지켜본다(안 부르면 최대 15초 늦다). macOS의 `watchFolder`는 하위 폴더까지 알려 주므로 보고 있는 파일(또는 폴더 자체)이 든 묶음에만 `load`를 부른다.
- **통합 때 필요한 일.** (1) `load`가 내용이 같으면 화면을 건드리지 않아야 한다. 지금 `load`는 매번 "불러오는 중…"으로 바꿨다가 새 id로 다시 그리므로 15초마다 화면이 깜박이고 스크롤이 처음으로 돌아간다. (2) `load`가 사라진 파일(`readTextFile`이 `null`)과 읽기 실패를 구분해야 한다(04). (3) 안내 화면(`renderNotice`)에 `this.renderActions(t)`를 붙일지 결정한다. 머리줄 버튼은 파일이 있으면 어떤 상태에서도 보인다.
- **미검증(06에서 확인).** 경계 4 전부: 실제 수정·삭제·복원, 버튼 둘의 실제 동작, 링크 종류별 클릭, 좁은 폭에서의 말줄임, 아이콘이 실제로 그려지는지, 원문 보기의 모습, `on_link_click`이 넘기는 주소의 형태(상대 링크를 그대로 주는지), 링크로 연 문서가 뒤로 가기 기록에 쌓이는지(03 통합 뒤).
