# 01: 라우터 넘겨받기·되돌리기

**What to build:** 라우터 앱을 빌드하고, 넘겨받은 확장자의 기본 앱을 라우터로 바꾸는 넘겨받기, 전부 원래 앱에 돌려주는 되돌리기, 확장자별 현재 기본 앱과 원래 앱을 보여 주는 상태 보기를 만든다. 이 티켓에서 라우터는 받은 파일을 전부 원래 앱으로 넘긴다(사이드 뷰어 연결은 02). 명세의 초기 확장자 목록을 실제 macOS에서 하나씩 확인해, 넘겨받을 수 없거나 목록 밖 확장자까지 딸려 오는 것은 목록에서 빼고 그 결과를 기록한다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**명세:** `docs/features/side-viewer/spec.md` (AC-5, AC-4 중 "원래 앱 기록이 없을 때"의 기본값)

**파일 소유:** `mods/side-viewer/router/`(Swift 소스, 빌드 스크립트), 넘겨받은 확장자 목록 파일(`mods/side-viewer/` 아래, 이 티켓이 이름과 형식을 정한다), 원래 앱 기록의 형식, `.gitignore`

**설계 계약:**
- `mods/side-viewer/router/`: `docs/adr/0001-cmd-click-through-a-default-app-router.md`, 명세 "구현 결정"의 원래 앱 기록·확장자 실측 항목
- 확장자 목록 파일: 명세 "구현 결정"의 "넘겨받은 확장자 목록은 한 곳에 둔다"
- `.gitignore`: 없음 (`AGENTS.md`, `docs/agents/`, `docs/adr/` 확인)

**검증 방법:**
- 경계 2: 원래 앱 기록을 읽고 쓰는 형식의 테스트(기록이 라우터 자신으로 덮이지 않는 경우 포함)
- 경계 4: 실제 macOS에서 넘겨받기 → 상태 보기 → Finder에서 파일 열기(원래 앱에서 열림) → 되돌리기 → 상태 보기. 시스템 기본 앱 설정을 바꾸므로 실행 전 상태 보기 출력을 보관하고 끝에 되돌리기로 복구한다.

- [ ] 라우터 앱이 빌드되고 백그라운드 전용으로 실행된다(Dock에 나타나지 않는다)
- [ ] 넘겨받기가 확장자별 원래 앱을 기록한 뒤 라우터를 기본 앱으로 만든다
- [ ] 넘겨받기를 두 번 실행해도 원래 앱 기록이 라우터로 덮이지 않는다
- [ ] 되돌리기가 기록된 확장자 전부를 원래 앱으로 돌린다
- [ ] 상태 보기가 확장자별 현재 기본 앱과 기록된 원래 앱을 출력한다
- [ ] 넘겨받은 상태에서 Finder로 연 파일이 원래 앱에서 열린다(기록이 없으면 TextEdit, 이미지는 미리보기)
- [ ] 초기 목록의 확장자별 실측 결과(넘겨받음/제외와 이유)가 티켓 Comments에 남고, 제외된 확장자는 목록 파일에서 빠졌다
- [ ] 검증 뒤 이 머신의 기본 앱 설정이 실행 전 상태로 돌아왔다

## Comments

### 2026-11-11 실측 (macOS 26.7.1, 이 머신)

**되돌리기가 실제 macOS에서 실패했다.** `--restore`가 30개 확장자 전부에서 `could not restore`로 끝났고(44초, 종료 코드 1) 기본 앱은 하나도 돌아오지 않았다. 지시에 따라 다시 시도하지 않았다. 원인은 `미확인`이다(실패 당시 스크립트가 라우터의 오류 문구를 버리고 있었다. 이후 커밋에서 오류 문구가 보이게 고쳤다). 지금 이 머신은 아래 "넘겨받음" 30개 확장자가 라우터에 넘어가 있는 상태다. 라우터는 받은 파일을 원래 앱으로 넘기고 있어 Finder에서 여는 동작은 유지된다(`mdx`·`jsonc`는 TextEdit).

확인된 것:

- 빌드만 해도(넘겨받기 전) 어떤 앱도 열지 않던 `mdx`·`jsonc`는 라우터가 기본 앱이 된다. 라우터가 그 확장자의 유일한 후보이기 때문이다.
- 첫 넘겨받기는 `md`·`markdown` 두 개에서 30초씩 시간 초과로 실패했다(전체 83초). 곧바로 다시 실행하자 1.2초 만에 전부 성공했고 원래 앱 기록은 바뀌지 않았다. 첫 실패의 원인은 `미확인`.
- 넘겨받은 상태에서 목록 밖 확장자 76종, 제외한 확장자 11종, 확장자 없는 파일 5개의 기본 앱은 하나도 바뀌지 않았다.
- `open x.log` → Console 실행(기록된 원래 앱), `open x.mdx` → TextEdit 실행(기록 없음). 두 파일을 연달아 열어도 둘 다 열린다(처음 구현은 두 번째 파일을 잃어 고쳤다).
- 실행 중 라우터의 앱 종류는 `BackgroundOnly`다.
- 기본 앱은 파일 종류만이 아니라 확장자 단위로도 갈린다. 넘겨받기 전 `js`는 WebStorm, 같은 종류의 `mjs`는 Warp였다. 그래서 상태 보기와 원래 앱 기록은 그 확장자의 실제 파일에 물어본 결과를 쓴다.
- 넘겨받기 전 이 머신에는 목록의 어떤 종류에도 사용자가 직접 지정한 기본 앱이 없었다(모두 앱들의 선언에서 정해진 값).

| 확장자 | 파일 종류 | 결과 | 이유 |
|---|---|---|---|
| `md` `markdown` | `net.daringfireball.markdown` | 넘겨받음 | 종류의 확장자가 이 둘뿐 |
| `mdx` `jsonc` | 종류 없음(확장자 단위) | 넘겨받음 | 원래 앱이 없어 기록도 없다. 되돌리면 TextEdit이 된다 |
| `png` `gif` `webp` | 각자의 종류 | 넘겨받음 | 딸려 오는 확장자 없음 |
| `log` `json` `css` `py` `swift` `c` `h` `sh` `zsh` `xml` `csv` | 각자의 종류 | 넘겨받음 | 딸려 오는 확장자 없음 |
| `yaml` `yml` | `public.yaml` | 넘겨받음 | 종류의 확장자가 이 둘뿐 |
| `toml` `cjs` `jsx` `tsx` `scss` `go` `rs` `kt` `sql` | 종류 없음(확장자 단위) | 넘겨받음 | 그 확장자만 넘어온다 |
| `ts` | `public.mpeg-2-transport-stream` | 넘겨받음 | 시스템이 동영상으로 분류하는 것은 사실로 확인. 확장자는 `ts` 하나뿐이고 이 머신의 원래 앱도 Warp(코드로 취급)였다. `.ts` 동영상 파일도 라우터를 거친다 |
| `txt` | `public.plain-text` | 제외 | 넓은 종류. `text`와 `README`·`LICENSE` 같은 확장자 없는 텍스트 파일이 같은 종류다 |
| `jpg` `jpeg` | `public.jpeg` | 제외 | 목록 밖 `jpe`가 딸려 온다 |
| `svg` | `public.svg-image` | 제외 | 목록 밖 `svgz`가 딸려 온다(원래 앱이 Whale로 `svg`와 다름) |
| `js` `mjs` | `com.netscape.javascript-source` | 제외 | 목록 밖 `jscript`·`javascript`가 딸려 온다. `js`(WebStorm)와 `mjs`(Warp)의 원래 앱이 달라 종류 단위로는 원래대로 돌릴 수 없다 |
| `rb` | `public.ruby-script` | 제외 | 목록 밖 `rbw`가 딸려 온다(원래 앱이 TextEdit으로 `rb`와 다름) |
| `java` | `com.sun.java-source` | 제외 | 목록 밖 `jav`가 딸려 온다 |
| `cpp` | `public.c-plus-plus-source` | 제외 | 목록 밖 `cp`·`c++`·`cc`·`cxx`가 딸려 온다 |
| `diff` `patch` | `public.patch-file` | 제외 | 두 확장자의 원래 앱이 달라(Warp, TextEdit) 종류 단위로는 원래대로 돌릴 수 없다 |

제외한 확장자는 분석만으로 뺐고 실제로 넘겨받아 보지는 않았다. `jpg`·`jpeg`·`svg`가 빠져 명세 AC-3의 이미지 목록과 어긋난다.
