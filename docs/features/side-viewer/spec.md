# 명세: 사이드 뷰어

Status: ready-for-agent

통합 기준: 브랜치 `feat/side-viewer`, 기준 SHA `e22ae7babba5a54ba0ba6c048754b8f62fac0488` (`main`)

용어는 루트 `GLOSSARY.md`를 따른다. 여는 방법의 결정 근거는 `docs/adr/0001-cmd-click-through-a-default-app-router.md`다.

## 문제

Herdr 앱에서 에이전트가 대화 중에 파일 경로(마크다운 문서, 코드, 이미지)를 언급하면, 그 파일을 보려고 다른 앱으로 넘어가야 한다. cmd-클릭하면 파일이 기본 앱에서 따로 열려 대화와 나란히 볼 수 없다.

## 해결

에이전트 대화의 파일 경로를 cmd-클릭하면 그 파일이 대화 오른쪽의 사이드 뷰어에 열린다. 마크다운은 렌더링해서, 코드·텍스트는 문법 색상이 있는 읽기 전용으로, 이미지는 그림으로 보여 준다. Herdr 밖에서 같은 파일을 열면 지금까지 쓰던 앱에서 그대로 열린다.

## 사용자 스토리

1. Herdr 사용자로서, 에이전트 대화의 마크다운 경로를 cmd-클릭해 오른쪽에서 렌더링된 문서를 보고 싶다. 대화를 떠나지 않고 읽기 위해서다.
2. Herdr 사용자로서, 코드·텍스트 파일 경로를 cmd-클릭해 문법 색상과 줄 번호가 있는 읽기 전용 화면으로 보고 싶다.
3. Herdr 사용자로서, 이미지 경로를 cmd-클릭해 오른쪽에서 그림을 보고 싶다.
4. Herdr 사용자로서, 사이드 뷰어가 이미 열려 있을 때 다른 경로를 누르면 창이 더 쪼개지지 않고 같은 뷰어의 내용만 바뀌길 원한다.
5. Herdr 사용자로서, 뒤로 가기로 직전에 보던 파일로 돌아가고 싶다.
6. Herdr 사용자로서, 에이전트가 파일을 고치면 사이드 뷰어가 스스로 새로고침되길 원한다.
7. Herdr 사용자로서, 마크다운 문서 안의 다른 마크다운 링크를 눌러 같은 뷰어에서 이어 읽고 싶다.
8. Herdr 사용자로서, 마크다운의 원문과 렌더링 결과를 오가며 보고 싶다.
9. Herdr 사용자로서, 보고 있는 파일을 원래 앱으로 열거나 Finder에서 위치를 보고 싶다.
10. macOS 사용자로서, Finder에서 같은 종류의 파일을 열면 예전처럼 원래 앱에서 열리길 원한다.
11. macOS 사용자로서, 명령 하나로 넘겨받은 확장자 전부를 원래 앱에 되돌리고 싶다.
12. macOS 사용자로서, 지금 어떤 확장자가 라우터에 넘어가 있고 원래 앱이 무엇인지 확인하고 싶다.
13. Herdr 사용자로서, 뷰어가 그릴 수 없는 파일을 눌러도 오류 없이 안내를 보고 원래 앱으로 열 수 있길 원한다.
14. Herdr 사용자로서, Herdr가 응답하지 않아도 내 클릭이 사라지지 않고 원래 앱에서 열리길 원한다.

## 인수 조건

검증 경계는 아래 "테스트 결정"의 네 가지를 가리킨다.

| ID | 관측할 결과 | 검증 경계 |
|---|---|---|
| AC-1 | Herdr가 앞에 있고 현재 탭에 사이드 뷰어가 없을 때 넘겨받은 확장자의 파일이 열리면, 포커스된 pane의 오른쪽에 사이드 뷰어 pane이 새로 생기고 그 파일을 보여 준다. | 경계 2, 경계 4 |
| AC-2 | 현재 탭에 사이드 뷰어가 보이는 상태에서 다른 파일이 열리면 pane 수는 그대로이고 그 뷰어의 내용만 바뀐다. 뒤로 가기는 직전 파일을 다시 보여 주고, 기록이 없으면 뒤로 가기가 보이지 않는다. | 경계 1, 경계 2, 경계 4 |
| AC-3 | 확장자에 따라 보기가 정해진다. 마크다운(`md markdown mdx`)은 렌더링, 이미지(`png jpg jpeg jpe gif webp svg svgz`)는 뷰어 폭을 넘지 않는 그림, 나머지 넘겨받은 확장자는 줄 번호와 문법 색상이 있는 읽기 전용 코드 보기다. 색상 언어를 모르는 확장자는 색 없이 보여 준다. | 경계 1, 경계 3, 경계 4 |
| AC-4 | Herdr가 앞에 있지 않을 때 넘겨받은 확장자의 파일이 열리면 그 확장자의 원래 앱에서 열리고, 사이드 뷰어는 열리거나 바뀌지 않는다. 원래 앱 기록이 없으면 TextEdit(이미지는 미리보기)에서 열린다. | 경계 2, 경계 4 |
| AC-5 | 넘겨받기는 묶음 단위로 한다. 묶음을 지정하지 않으면 마크다운과 이미지 묶음만, `code`를 지정하면 코드 묶음도 넘겨받는다. 실행하면 먼저 macOS 확인 창이 몇 번 뜰지 알려 준 뒤, 대상 확장자마다 원래 앱을 기록하고 라우터를 기본 앱으로 요청한다. 되돌리기는 라우터가 쥐고 있는 기록된 확장자 전부를 원래 앱으로 요청한다. 상태 보기는 확장자별 현재 기본 앱과 기록된 원래 앱을 출력한다. 넘겨받기를 두 번 실행해도 원래 앱 기록이 라우터 자신으로 덮이지 않는다. 사용자가 확인 창에서 기존 앱 유지를 고른 확장자는 바뀌지 않으며, 명령은 이를 오류가 아니라 "유지를 선택함"으로 구분해 어떤 확장자인지 알려 준다. | 경계 2(기록 형식, 묶음 선택, 거절 구분), 경계 4 |
| AC-6 | 보고 있는 파일이 디스크에서 바뀌면 클릭 없이 내용이 갱신된다. 파일이 사라지면 "이 파일은 더 이상 없습니다" 안내로 바뀌고, 다시 생기면 내용이 돌아온다. | 경계 4 |
| AC-7 | 마크다운 보기 안의 링크는 대상에 따라 다르게 동작한다. 마크다운 파일은 같은 뷰어에서 열리고 뒤로 가기 기록에 쌓인다. `http`·`https`·`mailto`는 시스템 기본 처리기로 열린다. 그 밖의 로컬 파일은 Finder에서 위치만 보여 주고 실행하지 않는다. 상대 링크는 보고 있는 문서의 폴더를 기준으로 푼다. | 경계 1, 경계 4 |
| AC-8 | 뷰어 머리줄에 파일 이름과 폴더가 보이고, 마크다운일 때만 원문/렌더링 전환이 있으며, "원래 앱으로 열기"와 "Finder에서 보기"가 동작한다. "원래 앱으로 열기"는 라우터로 되돌아오지 않는다. | 경계 2, 경계 4 |
| AC-9 | 그릴 수 없는 경우에는 내용 대신 이유 안내와 "원래 앱으로 열기"·"Finder에서 보기"만 보여 준다. 대상은 1 MB를 넘는 텍스트, 20 MB를 넘는 이미지, 넘겨받은 확장자가 아닌 파일, 읽을 수 없는 파일, 빈 파일("이 파일은 비어 있습니다")이다. 어떤 경우에도 mod 오류가 나지 않는다. | 경계 1, 경계 3, 경계 4 |
| AC-10 | 설치 스크립트는 mod를 Herdr 앱 홈에 복사하고 `herdr-app check`를 통과시키며 라우터 앱을 빌드한다. 기본 앱 넘겨받기는 설치 스크립트가 하지 않고, 사용자가 별도 명령으로 실행한다. | 경계 3, 경계 4 |
| AC-11 | Herdr가 앞에 있어도 `herdr-app` 실행 파일이 없거나 뷰어를 여는 명령이 오류를 내면 그 파일은 원래 앱에서 열린다. | 경계 2 |

## 구현 결정

- **구성 요소 세 가지.** 사이드 뷰어 mod(`mods/side-viewer/`), 라우터 앱(`mods/side-viewer/router/`, Swift로 빌드하는 백그라운드 전용 앱), 라우터가 부르는 분기 스크립트(`mods/side-viewer/open.sh`).
- **분기는 스크립트가 한다.** 라우터 앱은 "열린 파일 경로"와 "그때 앞에 있던 앱"만 분기 스크립트에 넘긴다. 판단을 스크립트에 두어 가짜 명령으로 테스트할 수 있게 한다.
- **Herdr 판별.** 앞에 있던 앱의 경로가 `Herdr.app`을 포함하거나 이름이 `herdr-app`이면 Herdr로 본다. 실행 중인 Herdr가 번들 ID를 보고하지 않을 수 있다는 참고 레포의 관찰을 따른 것이며, 이 저장소에서는 `미확인`이다.
- **뷰어에 넘기는 약속.** 스크립트는 요청(고유 ID와 파일 경로)을 mod의 데이터 폴더(`data/side-viewer/`)에 쓰고 `side-viewer.show` 명령을 보낸다. 현재 보이는 사이드 뷰어가 요청을 가져가며 같은 ID로 응답 파일을 쓴다. 약 0.4초 안에 응답이 없으면 스크립트가 `pane.split`(오른쪽, mod `side-viewer`, props에 파일)을 실행한다. mod 명령은 화면에 보이는 사본에만 닿기 때문에 응답 확인이 필요하다.
- **넘겨받은 확장자 목록은 한 곳에 둔다.** 라우터 빌드와 mod의 보기 판별이 같은 목록을 읽고, 목록은 마크다운·이미지·코드 세 묶음으로 나뉜다. 목록(2026-11-11 실측 반영): `md markdown mdx` / `png jpg jpeg jpe gif webp svg svgz` / `log json jsonc yaml yml toml js mjs cjs jsx ts tsx css scss py go rs rb java kt swift c h cpp sh zsh sql xml csv`와, 같은 파일 종류라 함께 넘어오는 형제 확장자(`js`의 `jscript javascript`, `rb`의 `rbw`, `java`의 `jav`, `cpp`의 `cp c++ cc cxx`). `html`은 브라우저 기본 설정과 얽혀 넣지 않는다. `txt`는 확장자 없는 텍스트 파일(`README` 등)까지 딸려 와서, `diff patch`는 한 종류 안에서 원래 앱이 서로 달라 원래대로 돌릴 수 없어서 넣지 않는다.
- **확장자 실측과 확인 창.** macOS는 확장자가 아니라 파일 종류 단위로 기본 앱을 정하고, 기본 앱을 바꾸는 요청마다 종류별로 사용자 확인 창을 띄운다(2026-11-11 실측: 확장자 30개에 창 약 26번, 같은 종류의 확장자는 한 창으로 묶여 나온다. 넘겨받기와 되돌리기 양쪽 모두 뜬다). 앱이 이 창을 끌 수 없으므로 기본 넘겨받기 범위를 마크다운·이미지 묶음으로 좁히고 코드 묶음은 선택으로 둔다. 사용자가 "유지"를 고르면 요청은 거절로 끝나고(`The file couldn’t be opened.`) 기본 앱은 바뀌지 않는다. 형제 확장자가 딸려 오는 종류는 형제를 목록에 함께 넣는다. `ts`는 시스템이 MPEG-2 동영상으로 분류하지만 그 종류의 확장자가 `ts` 하나뿐이라 넘겨받는다(`.ts` 동영상 파일도 라우터를 거쳐 원래 앱으로 간다).
- **원래 앱 기록.** 넘겨받기 전에 확장자(파일 종류)별 기본 앱의 번들 ID를 데이터 폴더에 기록한다. 이미 라우터가 기본 앱인 항목은 기록을 덮지 않는다. 되돌리기는 이 기록으로 복구한다.
- **보기 판별.** 확장자 → 보기(마크다운·코드·이미지·그릴 수 없음)와 코드 보기의 색상 언어를 정하는 순수 모듈. 앱의 코드 편집기가 모르는 언어 이름은 색 없이 그린다(TypeScript·JSX는 JavaScript 색상을 쓴다).
- **기록.** 뷰어 사본마다 방문 기록 스택을 갖는다. 새 파일을 열면 쌓고, 뒤로 가기는 꺼낸다. 같은 파일을 다시 열면 쌓지 않는다.
- **새로고침.** 보고 있는 파일의 폴더를 `watchFolder`로 지켜보고, 놓친 변경에 대비해 15초마다 다시 확인한다.
- **이미지 그리기.** Herdr는 앱 홈 아래의 실제 폴더에 있는 이미지만 그린다(참고 레포의 관찰, `미확인`). 그래서 이미지 확장자와 파일 머리 바이트가 모두 맞는 파일만 데이터 폴더에 복사해 그리고, 30일 동안 건드리지 않은 사본은 지운다.
- **화면.** 머리줄 40px(뒤로 가기, 파일 이름 13px 굵게, 폴더 11px 흐리게, 오른쪽에 버튼들), 본문은 `theme()` 색을 쓴다. 마크다운 본문은 최대 폭 860px로 가운데 정렬한다. 안내 문구: "불러오는 중…", "이 파일은 비어 있습니다.", "이 파일은 더 이상 없습니다.", "뷰어에서 열기에는 너무 큽니다.", "이 종류의 파일은 뷰어에서 열 수 없습니다."
- **줄 번호.** `app.ts:12`처럼 줄 번호가 붙은 경로를 눌러도 뷰어는 파일의 처음부터 보여 준다. macOS가 라우터에 파일만 넘길 것으로 보기 때문이며 `미확인`이다. 구현 중 줄 번호가 전달되는 것이 확인돼도 이번 범위에서는 쓰지 않는다.
- **저장소 구조.** `herdr-worktrees`와 같다: `mods/side-viewer/`, `install.sh`, `RECIPE.md`, `README.md`, `LICENSE`. 참고 레포(jgrecoarroyo/herdr-markdown, MIT)는 동작 방식만 참고하고 코드는 새로 쓴다.
- **플랫폼 제약.** mod는 gpui-kit으로 쓰며 HTML·`setTimeout`·Node API를 쓸 수 없다. 플랫폼 계약은 `~/.config/herdr-app/AGENTS.md`와 `herdr.d.ts`다.

## 상태와 실패

- **불러오는 중:** 파일을 읽는 동안 "불러오는 중…".
- **빈 파일, 사라진 파일, 너무 큰 파일, 그릴 수 없는 종류, 읽기 실패:** AC-6, AC-9의 안내.
- **상호작용:** 뒤로 가기, 원문/렌더링 전환, 버튼 둘, 마크다운 링크. 버튼은 마우스를 올리면 배경이 바뀐다.
- **반응형:** 뷰어 폭이 좁아지면 파일 이름과 폴더를 말줄임하고 버튼은 유지한다. 이미지는 뷰어 폭을 넘지 않는다.
- **접근성:** 색은 `theme()`을 따라 밝은·어두운 테마 모두에서 읽힌다. 키보드로 뷰어 안을 이동하는 기능은 이번 범위 밖이다.
- **Herdr 무응답·명령 오류:** AC-11대로 원래 앱에서 연다.
- **라우터 미설치 또는 넘겨받기 전:** 아무것도 바뀌지 않는다. cmd-클릭은 지금처럼 기본 앱을 연다.

## 테스트 결정

좋은 테스트는 밖에서 보이는 동작만 본다: 입력(경로, 링크, 요청, 앞에 있던 앱)에 대한 결과(보기 종류, 다음 상태, 실행된 명령).

| 경계 | 방법 | 잡는 실패 | 못 잡는 범위 |
|---|---|---|---|
| 경계 1 | 순수 모듈 단위 테스트(`node --test`): 보기 판별, 방문 기록, 마크다운 링크 처리, 요청 해석, 크기 제한 판단 | 확장자·링크·기록의 잘못된 판단, 경계값(1 MB, 20 MB) 오류 | 화면 모양, 실제 파일 읽기와 감시 |
| 경계 2 | 분기 스크립트 테스트: 가짜 `herdr-app`·`open`과 임시 데이터 폴더로 실행해 어떤 명령이 불렸는지 확인 | Herdr 판별 오류, 응답 대기 뒤 분할 누락, 실패 시 원래 앱으로 넘기지 않는 경우, 원래 앱 기록 해석 오류 | macOS가 라우터를 실제로 부르는지, 라우터 앱의 Swift 코드 |
| 경계 3 | `herdr-app check mods/side-viewer` | mod 로드 실패, 첫 그리기 오류 | 클릭 뒤의 화면, 비동기로 나중에 그려지는 상태, 배치 |
| 경계 4 | 실제 앱에서 손으로 확인하는 목록(`RECIPE.md`의 "Done when") | cmd-클릭부터 화면까지의 전체 연결, 넘겨받기·되돌리기의 실제 효과 | 이후의 회귀(자동으로 다시 돌지 않음) |

테스트 선례는 `herdr-worktrees`의 `mods/*/*.test.mjs`(`node --test`, 순수 모듈만 대상)다. 경계 4를 자동화하지 않는 이유: 2026-11-11에 화면 자동화로 cmd-클릭을 시도했으나 사용 중인 창과 충돌해 결과를 신뢰할 수 없었다.

## 범위 밖

- 웹 주소(`http`, `https`)를 사이드 뷰어로 열기
- 다른 머신의 터미널에 나온 경로
- pdf·zip 등 바이너리 내용 표시, `html`
- 파일 편집
- 마크다운 본문 안의 이미지 표시, 코드 블록 복사 버튼
- 줄 번호 위치로 이동
- 단축키로 경로 목록을 띄우는 picker
- Linux·Windows

## 참고

- cmd-클릭이 에이전트 창에서 절대 경로, 상대 경로, 줄 번호 포함 경로, 코드 표기 안의 경로를 모두 기본 앱으로 넘긴다는 것은 2026-11-11에 사용자가 직접 눌러 확인했다(`herdr-app 0.1.13`).
- 확장자 없는 파일과 목록에 없는 확장자는 cmd-클릭해도 지금처럼 원래 앱에서 열린다.

### 의존성 간선

- 01: 선행 없음
- 02 ← 01
- 03 ← 02
- 04 ← 02
- 05 ← 02
- 06 ← 01, 03, 04, 05

실행 가능: 01. 대기: 02, 03, 04, 05. 통합 검증: 06.

03·04·05는 서로 선행이 아니지만 아래 연결 파일을 함께 고친다. 별도 worktree에서만 병렬로 진행하고, 같은 작업 트리에서는 03 → 04 → 05 순서로 한다. 05의 "링크로 연 문서가 뒤로 가기 기록에 쌓인다"는 03의 방문 기록 모듈을 쓰므로, 03이 통합되기 전에 05를 끝냈다면 그 항목은 06에서 확인한다.
